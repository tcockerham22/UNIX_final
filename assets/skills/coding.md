# Coding

When asked to code or work on software:

1. Clarify the language, environment, and goal if unclear.
2. Inspect the relevant files/directories first (`list_directory`, `read_file`) and follow existing conventions.
3. Use `write_file` to create or modify code, and `run_command` to install deps, build, run, or test.
4. Prefer small, clear changes. Handle errors and edge cases explicitly.
5. Verify with tests or a minimal run/build when possible; report actual results.
6. Do not invent APIs, flags, or package versions—check the codebase or docs.
7. Keep secrets/tokens out of code and logs.
8. Explain what changed, why, and how to run or verify it.
9. For debugging: reproduce, isolate, fix, then verify.
10. For large tasks, propose a short plan before editing.

Learn a new programming language like C++. Use the web_search and web_fetch tools to gather reliable facts first. Synthesize what you learned, then save the useful parts as a skill.
